1 · The Locked Spec (what we are building)

Cognitive job: Given a proposed action and its context, decide whether to execute it now, ask the counterparty for one named missing fact, defer because the missing thing is time, escalate because no confidence level would justify the cost of being wrong, or refuse because the action should not happen regardless of who asks or how certain anyone is — and produce a full, replayable audit trail for that decision. The hard part is not calling the action; it is knowing when not to. Binary allow/deny is the easy case — ask, defer, and escalate are not failure modes, they are the answer most of the time.

Inputs: a proposed action (domain, action type, parameters, an estimated cost and reversibility class) plus a set of typed Signals bearing on it, each carrying its provenance (where it came from), freshness (how old it is), and its own confidence.  →  Outputs: one of the five outcomes, each surfacing confidence, a risk score, the exact evidence (signals) used, any missing information named explicitly (and who or what can supply it), the action's reversibility class, and an audit record of the inputs, signals, reasoning, and rule that produced it.

Autonomy level: Fully autonomous for execute — but only inside the confidence bar that the reversibility × cost model sets for that specific action; every other outcome exists precisely because full autonomy stops being appropriate at that point, and deliberately hands control elsewhere: ask to the counterparty, defer to time, escalate to a human, refuse to no one.  |  Human-in-the-loop points: humans author the cost/reversibility tables and the per-domain policies, and a human owns every escalate after the fact; no human sits inside the per-request decision loop for the other four outcomes — the mapping from signals to outcome is a deterministic function, not an LLM call, precisely so the same inputs always replay to the same outcome.

Failure tolerance: Fail toward the least reversible-harm outcome. A missing, stale, or unprovenanced signal must push the decision toward ask/defer/escalate, never toward a silently-optimistic execute. There is deliberately no LLM anywhere in the decision path — the engine is a pure function of typed signals, so a decision that could not be reproduced from its own recorded inputs is itself treated as a defect.  |  Trust boundary: everything offered as context for an action — a claimed identity, a claimed history, a claimed urgency — is untrusted until it arrives as a Signal carrying its source and freshness; a claim with no provenance or one past its freshness threshold is treated as missing information, never as evidence.

2 · Definition of Done (binary gates — checked by the VERIFIER, not the maker)

Dependency direction inward, zero cycles (modular-architecture gate)
npm run typecheck clean AND npm test green
One verify pass by a separate agent/model (L4)
No context-graph.json invariant violated by the change
Every decision names the signals it used and the rule that produced it — never a bare outcome (explainability gate)
A decision is reproducible: the same recorded inputs yield the same outcome (replay gate)
An ask names the specific missing fact; a defer names what it is waiting for; an escalate names why no confidence would suffice (named-outcome gate)
No decision path reads a signal without its provenance and freshness (trust-boundary gate)
The live demo URL returns 200 to an anonymous request (deliverable gate — the brief requires a live demo)
A clean clone plus install plus test passes with no credentials configured (clean-clone gate)

A milestone is DONE only when every box above is checked by the verifier. There is deliberately no LLM in the decision path, so any generic "LLM schema-validation" gate from a template does not apply here and was dropped.
